**「Impact」** This demonstrates a novel approach to neural rendering and model compilation, potentially enabling other algorithms to be embedded in transformers without training, though the extreme computational cost \(40 minutes per frame on a B200\) limits practical use to research and proof-of-concept.

At inference time, demonstrations of a previously unseen task update the model&\#x27;s recurrent memory, and the query is solved through iterative computation in a high-dimensional latent workspace without decoding intermediate reasoning into language. A 150M-parameter configuration achieves 29.5% pass@2 on ARC-AGI-1 at a computed cost of $0.00070 per task, reportedly breaking the cost-accuracy Pareto frontier. **「Background」** In-context learning typically relies on transformer architectures that process demonstrations and queries in a single forward pass, often with high computational cost. BDH-CQ instead uses recurrent memory and latent reasoning, which may offer a more efficient alternative by avoiding the need to decode intermediate steps into language.

**「Impact」** If the reported results hold, BDH-CQ could enable significantly cheaper AI reasoning on abstract tasks, potentially lowering the barrier for deploying such systems in cost-sensitive applications. ### [PostgreSQL to\_char Flaw Allows Code Execution](https://www.postgresql.org/support/security/CVE-2026-14669/) ⭐️ 8.0/10

PostgreSQL disclosed a critical vulnerability, CVE-2026-14669, in the to\_char\(timestamptz\) function when processing overly long POSIX timezone abbreviations, leading to a heap buffer overflow. This flaw allows database users with low-privileged accounts to execute arbitrary code with the operating system permissions of the PostgreSQL service process. The vulnerability has a CVSS score of 8.8 and requires a low-privileged database account, not unauthenticated access. Affected versions include PostgreSQL 18.5, 17.11, 16.15, 15.19, and 14.24 and earlier. Since 18.5 was not officially released due to regression issues, 18-series users should upgrade directly to 18.6; other users should upgrade to 17.11, 16.15, 15.19, or 14.24 respectively. These minor updates do not require a database dump or pg\_upgrade; simply update the program files and restart the service.

telegram · zaihuapd · Aug 14, 14:35

**「Background」** PostgreSQL&\#x27;s to\_char function converts timestamps to formatted strings, and its handling of timezone abbreviations can be exploited if the input is malformed. Heap buffer overflows occur when a program writes data beyond the allocated memory, potentially allowing attackers to corrupt memory and execute arbitrary code. This vulnerability is part of a series of security fixes in PostgreSQL&\#x27;s minor releases, which typically address bugs and security issues without requiring major upgrades.

**「Impact」** Affected PostgreSQL users should upgrade to the specified minor releases immediately to prevent potential arbitrary code execution by low-privileged database users, which could compromise the entire database server and underlying operating system.

### [Google Advances Homomorphic Encryption for Private AI](https://blog.google/security/how-google-is-making-private-ai-practical-with-homomorphic-encryption/) ⭐️ 7.0/10

Google has announced progress in making homomorphic encryption \(HE\) practical for private AI, aiming to allow computations on encrypted data without exposing the underlying information. This development is significant because it could enable AI services to process sensitive data without compromising privacy, addressing a major barrier to cloud-based AI adoption. However, the technology still faces substantial challenges, particularly high computational overhead—often cited as around 1000x—which limits its commercial viability. Google&\#x27;s efforts focus on optimizing HE schemes and integrating them with machine learning models, but practical deployment remains uncertain. The announcement has sparked debate about whether HE is a viable solution compared to local processing with open-weight models.

hackernews · u1hcw9nx · Aug 14, 15:43 · [Discussion](https://news.ycombinator.com/item?id=49300314)

**「Background」** Homomorphic encryption \(HE\) is a cryptographic technique that allows computations to be performed on encrypted data without decrypting it first, producing an encrypted result that, when decrypted, matches the result of operations on the plaintext. This property makes it theoretically possible to run AI models on sensitive data while keeping that data private from the service provider. However, HE has historically been impractical for machine learning due to extremely high computational overhead—often on the order of 10^3 times slower than plaintext inference—and the need for specialized expertise to convert models to work on encrypted inputs. Google&\#x27;s HEIR \(Homomorphic Encryption Intermediate Representation\) is an open-source compiler designed to automate this conversion, taking pre-trained AI models that operate on unencrypted data and transforming them to operate on encrypted inputs, thereby aiming to make private AI more practical for real-world applications.

**「Impact」** If Google&\#x27;s HE optimizations succeed, organizations handling sensitive data \(e.g., healthcare, finance\) could use cloud AI without exposing raw data, but the current overhead makes it impractical for most real-time applications.

**「Community Discussion」** Commenters are skeptical about HE&\#x27;s practicality, citing high overheads \(~1000x\) and questioning its advantage over local models. Some suggest hybrid approaches \(running parts of the model locally\) but note that even then, privacy guarantees are limited. Others speculate the announcement is partly to secure funding from AI-focused executives.
